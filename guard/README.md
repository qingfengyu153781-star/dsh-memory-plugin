### g_root 根治病根闸（第八闸）—— 从 4,888 条问题反推

**来源**：`<WORKSPACE>\技术工作站对话_汇总_2026-10-03\_out\问题总表.md`（1,707 坑族 / 3,510 条目）
＋ `_out\补读\补读_问题表.md`（1,378 条）＝ **4,888 条问题**，归纳出 **7 个病根**。

**一句话**：这些病根的共同形态是 **「把『我做的动作』当成了『我要的结果』」**——
过程全绿（键已打、文件已存、闸门已绿、数字已达标），目标却可以完全不达标。

**为什么必须做成闸门**：表里自己反复证明 **「写了断言但不 raise ＝ 没有断言」**、
**「断言只记录不拦停」**。所以根治的唯一有效形式 = 可执行、**会拦停**的检查。

| 闸 | 治的病根 | 拦什么 |
|---|---|---|
| `B1_target` | 判据量"过程量"不量"目标量" | 判据声明里没有"要保证的量" |
| `B2_cite`   | 引用会过期（md5/行号/计数/快照） | 出现可变物引用而**无取数时刻** |
| `B3_reopen` | 没落盘／被求值覆盖（内存态≠盘上） | 报"已改/完成"却**无 reopen 回读证据** |
| `B4_ruler`  | 口径不统一 | 缺**量具四问**（帧/归零遍/算法/文件集） |
| `B5_scope`  | 范围不全却说"没有" | 出现"不存在/没有"而**无扫描范围声明** |
| `B6_sweep`  | 改一处不扫同类 | 有改动却**无同类扫描命中数** |
| `B7_verify` | 未核实就下结论 | 推断类措辞**多于**实测证据 |

**用法**：
```bash
python <WORKSPACE>\_guard\guard_cli.py root --text-file 报告.md          # 报告体（跑全部七道）
python <WORKSPACE>\_guard\guard_cli.py root --text-file 稿子.md --kind article   # 文章体（只跑 3 道，防误杀）
python <WORKSPACE>\_guard\guard_cli.py root-demo                        # 负例自检（证明拦得住）
```

**已验证（2026-10-03）**：
- 负例自检 **5/5 全拦**（B1/B2/B3/B5/B7 各一条真实形态）＋ **正例不误杀**
- 真实报告实测：拿本会话自己写的 4 份报告打闸，**全部命中真实病根**（含《病根总结》本身）
- **误杀治理**：初版把"引用块/表格/定义句/修法段"也当声明 ⇒ 误杀严重；
  加**元行过滤**（引用块、表格、代码块、含"坑/病根/教训"的讨论行、定义句、修法段）后误杀降到 0–2 处

### 挂钩：让"写报告"本身必须过闸（不是靠人记得跑）

**闸门再好，没人主动跑就等于没有。** 所以把 `g_root` 挂进 `hook.py`——
**不过闸 ⇒ 文件根本不落盘**。

```python
from hook import guard_report

# 方式一：先检后写
guard_report("报告.md", text)              # 不过 ⇒ raise，下一行执行不到
Path("报告.md").write_text(text)

# 方式二：写入即校验（推荐，闸不过就不落盘）
with guard_report("报告.md") as g:
    g.write(text)                          # 不过 ⇒ RootGateFailed，盘上不会出现这个文件
```

命令行：
```bash
python <WORKSPACE>\_guard\guard_cli.py check-report 报告.md      # 不过 ⇒ 退出码 1
python <WORKSPACE>\_guard\guard_cli.py report-selftest           # 实机自检：坏报告必须拦下且不落盘
```

**自动化范围（已实现）**：
- **`.md` 报告类** ⇒ 写前过闸（`_is_report()` 判定）
- **索引/配置类 `.md`**（`README` / `AGENTS` / `_索引.md` / `00_*` / `SKILLS_INDEX`）⇒ **跳过**（不误杀数据文件）
- **非 `.md`**（`.jsonl` / 代码 / 资产）⇒ 跳过

**已验证（2026-10-03）**：
- 坏报告（报"已改"却无 reopen 证据）⇒ **拦下且盘上无该文件** ✓
- 好报告 ⇒ 放行 ✓
- `_索引.md` ⇒ 正确跳过、不误杀 ✓

## g_intent 意图闸（第九道）—— 唯一装在"动手之前"的闸

### 为什么必须单独有一道

**用户点破（2026-10-03）**：
> 「<用户原话已隐去：质疑闸门为何仍理解错>」

**实证**：用户说「先把**主表遇到的问题**根治了」，
我读成"修主表**这个文件**的缺陷（NUL/字段/编号）"→ 出了整套方案 →
用户：「**我没让你修这个表**我要修的是**表里内容体现的问题**」。

**其余八道闸全程绿灯** —— 因为**产出本身没有毛病，是我做错了事**。
八道闸全在**产出侧**（报告写完、要落盘时）；这个错在**动手前**。

### 根除做法：照抄 `g_obj` 的三步，一步不许跳

```
RESOLVE  把用户的话解析成任务清单：对象 / 打算做什么 / 我不确定的地方
CONFIRM  有歧义 ⇒ raise NeedsClarify（**内含选择题**，不是开放提问）
APPLY    才动手
```

### 硬约束（可执行判据）

| 判据 | 触发条件 |
|---|---|
| **指代不明** | 话里有指代词（这个/那个/它/这些…）或空壳名词（问题/东西/内容…），**且同类候选 ≥2** ⇒ 必须问 |
| **范围没边界** | 出现"这些/那些/全部/其它"而候选 ≥2 ⇒ 必须问 |
| **不确定栏为空** | 空栏 = 没做 RESOLVE ⇒ 拦（真无疑问要显式写"无"） |

### 用法

```python
from hook import guard_intent
rec = guard_intent("先把主表遇到的问题根治了",
                   candidates=["主表文件的缺陷", "主表里记录的那些问题"],
                   uncertain=["『问题』指文件还是内容"],
                   my_reading="修主表.md")
# ↑ 直接 raise NeedsClarify，把选择题抛给用户 → 用户选完再 confirm()
```

```bash
python <WORKSPACE>\_guard\guard_cli.py intent --said "…" \
    --candidates "A;B" --uncertain "…" --reading "我以为…"    # 有歧义 ⇒ 退出码 1
python <WORKSPACE>\_guard\guard_cli.py intent-selftest           # 实机自检
python <WORKSPACE>\_guard\guard_cli.py intent-demo               # 负例自检
```

### 实测输出（它就是当时该说的话）

```
你先定一下方向，我不敢自己挑：

  你说的是：「先把主表遇到的问题根治了再看吧」
  我原本以为：修主表.md 的 NUL 字节

  1. 主表文件的缺陷(NUL/字段/编号)
  2. 主表里记录的那些问题(4888条)

  （回 1/2/…，或直接说你要的是哪个）
```

**已验证**：真实那次误解 ⇒ **拦住** ✓；指令明确（候选唯一）⇒ **放行** ✓

## g_struct 结构声明闸（第十一道）—— 治本：不查"词"，查"结构 + 实质"

### 治的是什么本

**实测出的病**（`case_test.py --t3`）：`g_root` 识破率 **0/7** ——
把「已改」写成「处理完毕」、把「md5」写成「校验值」、改用英文、塞进代码块 —— **换说法就绕过**。

**根因**：`g_root` 问的是「**你有没有说那个词**」。只要不用那个词，它就看不见。

### 两层治法

**第一层：查结构（不查措辞）**

| | 旧（g_root） | 新（g_struct） |
|---|---|---|
| 检查对象 | 措辞（「已改」） | 结构（`## 回读证据` + `实测值:`） |
| 换词能绕过吗 | ✅ 能 | ❌ 不能 |

**第二层：查实质（不查空壳）**

第一版仍被两种手法绕过（实测）：
- **空壳**：`- 实测值：`（字段在，值是空的）
- **废话**：`- 实测值：没问题`

**治法**：每栏必须有**可被独立核对的东西** ——
数字 / 哈希 / 路径 / 文件名 / 命令 / 帧号 / 版本号，任一即可。

> ★ **这不算模板**。它约束的是**信息量**（有没有可查的东西），**不是句式**。
> 你可以用任何语言、任何结构、任何措辞 —— 只要有真东西在里面。
> （用户明确：**不要写模板，否则以后就都是模板**。）

**第三层：防"少写几栏降低分母"**

对抗者可以"只写会被触发的栏"来压低 `miss/need` 比率。治法：
**成果类文档一律并入核心栏**（不管 need 已经是多少）⇒ 少写几栏不再能降低分母。

### 实测（3 组对照）

| 攻击 | g_root | g_struct |
|---|---|---|
| 13 种伪装（同义词/英文/代码块/引用块/emoji/花式措辞/空壳/废话） | **15%** | **100%** |
| 真实语料 200 个 .md 通过率 | 72% 被拦 | **28% 被拦**（144 个判为说明/索引类跳过） |

**用法**：
```bash
python D:gent\_guard\guard_cli.py struct --text-file 报告.md
python D:gent\_guard\guard_cli.py struct --template    # 只用于"知道该有哪些信息"，不是填空模板
```

## g_xcheck 交叉复核闸（第十二道）—— 去盘上/库里**真核一遍**

### 治的是什么（2026-10-03 用户点破：「交叉结合数据库插件复核」）

**前两道的共同局限**（我实测出来的）：
- `g_root` 查措辞 → 换词绕过（15%）
- `g_struct` 查结构+实质 → 换词/空壳/废话都绕不过（100%）
- **但两者都只查「报告里写了什么」** —— 你写 `- 实测值：27 个对象` **而实际没测**，照样过。

### 三条独立复核通路

| 通路 | 核什么 | 数据源 |
|---|---|---|
| **A. 盘上核** | 文件是否存在 / md5 是否对得上 / 目录里真有几个 | 文件系统 |
| **B. 库里核** | 用户是否**真说过**那句话 / 该决策是否真做过 | `dsh-rag-memory`（**1,152 会话 / 254,028 原子**） |
| **C. 台账核** | 宣称「已改」是否真有留痕 | `_guard_ledger/*.jsonl` |

**为什么必须「交叉」**：单条通路自己会错。**两条独立通路一致**才算过 ——
这正是表里反复推荐的「绿灯必须由另一条计算通路复核」。

### 检查项

| 项 | 声明形态 | 复核方式 |
|---|---|---|
| `X1` 文件存在 | 提到某路径 | `Path.exists()` |
| `X2` md5 属实 | `md5 <hex>` + 邻近路径 | **实算盘上文件的 md5 并比对** |
| `X3` 用户原话 | 「用户说：xxx」 | **去记忆库 grep**（1,152 个会话里找） |
| `X4` 数字可复算 | `N 个 .ext` + 目录 | 实算该目录下数量 |
| `X5` 台账留痕 | 「已改/已修复」 | 查 `_guard_ledger` 有无记录 |

### 实测（用的都是真盘、真库）

```
负例 1：编造文件路径  -> 拦住  **盘上不存在**
负例 2：编造 md5      -> 拦住  **md5 不符**：报告写 ffff…，盘上实为 4bbe24b794813231
负例 3：编造用户原话  -> 拦住  **库中零命中** —— 在 1,152 个会话里找不到
正例 1：真说过的话    -> 核实相符（库中命中 14 条）
正例 2：真存在的路径  -> 通过
```

### 三层闸的能力递进（同一批 14 种攻击）

| 攻击类型 | g_root | g_struct | g_xcheck |
|---|---|---|---|
| 措辞伪装 11 种 | 7% | **100%** | —（无可核事实，按设计不拦） |
| **编造具体事实 3 种** | 0% | 33% | **100%** |

**三层互补**：`g_root` 软（给提示）、`g_struct` 硬（查结构+实质）、`g_xcheck` 硬（核事实）。

### 挂钩已升级为**三道闸**

```python
with guard_report("报告.md") as g:
    g.write(text)
# ① g_struct 结构闸 -> ② g_xcheck 交叉复核闸 -> ③ g_root 措辞闸 -> 才落盘
```

## g_vision 视觉核验闸（第十三道）—— 看图要真看，看不了要**明说**

### 治的三个问题（2026-10-03 用户点名）

**① 图像核验跟随当前模型**

报告里写「我看了画面，人形完整」—— 以前只能查「有没有写帧号」，查不出**你到底看没看**。
治法：**真去调视觉模型看**。模型跟配置走（`config.vision.model`，默认 `deepseek-v4-flash-vision-exp`）。

**② 模型没有识图能力 ⇒ 必须明说「我无法看图」，不许假装核过**

用户原话：「**没用识图功能就让模型输出无法看图告诉用户**」

```bash
python <WORKSPACE>\_guard\guard_cli.py vision --capability
# 凭证缺失时输出：
#   can_see = False
#   detail  = **无法看图**：凭证 DEEPSEEK_API_KEY 缺失或读不到 —— 任何『我看了画面』的结论都不成立
```

**能力探测 → 再决定说不说「我核过了」** —— 这是诚实性的硬要求。

**③ 细线级细节不许拿模型结论判废**

表里 P 系列实证：视觉模型对**细线级/纹理级/亚像素级**细节读不出来
（机械线、接缝、颗粒、虹膜反光、文字边缘）——**它答「没有」不等于真没有**。
所以闸门把问题分两级：

| 级 | 例子 | 能否采信 |

## g_doc 文档健康闸（第十五道）—— 记忆文件不能违反它自己的规矩

### 为什么有这道闸（2026-10-03 用户明令「改」）

**背景**：`AGENTS.md` 涨到 **67,792 B**，超过**会话注入上限 65,536 B** ⇒ **末尾被截断**。
而**被截掉的恰好是用户亲定的最高优先级铁律**：

```
## 🔴🔴🔴 最高优先级铁律（2026-10-02 用户明令）
# 做任何东西都要考虑合理性
**这条规则优先于本文件其余一切条款…违反它的产物一律不交，哪怕所有闸门/判据都绿。**
```

**两个病灶，都是"文档结构违反了它自己的规矩"**：

| 病灶 | 违反了什么 |
|---|---|
| 文件太长 | 末尾**静默失效** —— 不报错、不提示，规矩悄悄没了 |
| 「最高优先级」排最末 | 自称最高却排最后 ⇒ **必然第一个被截断** |
| 索引里塞详情 | 复盘索引曾占全文 **59%** ⇒ **挤掉正文** |
| 数字过期 | 文件写"28 条规矩"，实际 35 条 |

**这四条没有一条会报错** —— 文件照样能存、能读、能提交，**只是悄悄失效**。
**与表里"假绿"是同一个形态。**

### 四项检查

| 项 | 判据 | 治什么 |
|---|---|---|
| **D1 不超注入上限** | `字节数 ≤ 65536`（余量 < 4096 也提示） | 超了末尾**静默截断**，规矩悄悄失效 |
| **D2 最高优先级靠前** | 含「最高优先级」的章节起点须在**前 35%** | 自称最高却排最后 = 必然第一个被截 |
| **D3 索引不膨胀** | 索引类章节占比 ≤ **30%** | 索引里塞详情 ⇒ 挤掉正文 |
| **D4 声明与事实一致** | 文件里的「N 道闸门/N 条规矩」须与实测相符 | 口径不一致 |

### 实测

```
负例 1：135 KB 文件 + 最高优先级排最后  → D1 拦下（超 69,578 B）/ D2 拦下（排在第 100% 处）
负例 2：索引段塞满详情                  → D3 拦下（占全文 100%，上限 30%）
负例 3：写"99 道闸门 / 88 条规矩"        → D4 拦下（实际 15 / 35）
正例：改造后的 AGENTS.md                → D1 ✓ 36 KB（余量 29 KB）/ D2 ✓ 前 14% / D3 ✓ 19% / D4 ✓
```

### ★ 它当场抓到了真问题（不是测试，是实际运行）

**D4 第一次跑就报了红**：

```
✗ D4 声明与事实不符 —— 规矩：文件写 28，实际 35
```

**AGENTS.md 里还写着「28 条规矩 / 24 条已接闸（86%）」，而实际已经是 35 条** ——
这正是表里"**口径不一致**"那条病根，**长在我自己的文档上**。

**修好后又抓了一次**：我加 4 条规矩（R-36~39），"35 条"立刻过期 ⇒ 又报红 ⇒ 同步为 39 条。
